# 黑胶婚礼致谢 v0.2.3

默认包含银黑唱片轻摆、正向照片、左侧闪烁星光、右侧音波装饰和金白滚动文字。替换照片、名单、文案与音乐后导出横屏 1080p 视频。使用自带脚本和素材，不依赖作者的目录或剪映缓存，不输出剪映原生工程。

v0.2.3 让每次回复都带上当前下一步。画面参数、`assets/stars.mov` 和 v0.2.2 的内存与音乐规则保留。

先读 [收集材料](references/workflow.md)。不要让新手编辑 JSON 或输入命令。

## 对用户怎么说

主回复只留当前这一句。`scripts/check_environment.py` 通过时只表示「运行环境已就绪」，不要把它说成技能已经装进应用。用户确实刚在应用里安装成功时，才说：「技能已经装好。请发你要放进视频的照片。」已经装过就不要重复这句，也不要重报版本和检查过程。缺材料时只问当前一项。

不要给「打兼容补丁 / 装成常驻技能 / 直接出片」这种技术选择。滤镜文件怎么读由脚本判断，不要问用户要不要打补丁。不要把 `FFMPEG=`、字体完整路径、解压目录或 `.tools` 自检目录写进主回复；出错或用户追问再说明。失败要说清楚，不要为了短而藏起来。

检查是只读的。不要自动安装依赖，不要临时签名，不要去掉隔离。系统安全提示要尊重，不要把绕过说成更安全。

## 必须遵守

- 安装：运行 `scripts/check_environment.py`。通过就用它打印的那一句回复，然后等照片。不渲染。
- 「给我跑一下」「试一下」「做一个」不是同意占位演示，也不是同意合成测试音。没有照片就只问照片。
- 顺序一次只问一项：照片 → 新人姓名和日期 → 分组名单 → 致谢文案 → 音乐。已经给过的跳过。
- 普通「帮我做」直接问当前缺的那一项，不要先出通用稿。「做」或「跑一下」不是看预览的同意。
- 用户明确要看效果时，可以做一次标明的通用预览，结尾说明还不是正式版，并说出下一项。已有预览就接着定制。不要用喜字或示例名单冒充用户的材料。
- FFmpeg 启动不了就说明暂时不能导出，并马上问当前缺的那一项。先只读检查命令路径和常见安装位置，区分没找到、不能执行、没权限和实际运行失败。没有日志不要说系统拦截。需要安装时问是否同意按官网协助，不要只甩安装命令，也不要停在装好再来。不要换别的渲染软件，也不要把环境限制说成用户电脑没装。
- 没有音乐不能默认静音。只有用户明确说不要音乐，才静音。
- 音乐还没指定时，只问：原片同款、自己选歌，或明确静音。原片同款指五月天《如果我们不曾相遇》，只是曲名参考。包里没有这首歌，不要下载，也不要从技能包素材里取。没有文件就不能导出。
- MIT 许可不包括第三方音乐。用户应提供其有权使用的音频。从用户视频提取要对方明确要求，取出的是整条音轨，不构成歌曲授权。
- 齐了以后先给白话汇总，用户确认后才导出。正式尺寸是 1920×1080。
- 占位照片和化名要用户明确同意。合成测试音要另外明确同意，并且说明它不是客户的歌。
- 这个安装包没有示例照片和示例音乐。不要自己画占位图，也不要把合成声音说成客户的歌。
- 缺文件、音乐打不开、没有清单或输出目录已存在时，脚本会停止。不要改滤镜参数后换一个副本硬跑。

清单和渲染：

```bash
python3 -X utf8 scripts/check_environment.py
python3 -X utf8 scripts/gate.py decide --state 状态.json
python3 -X utf8 scripts/gate.py manifest --state 状态.json --config 客户配置.json --out 新的输出目录 --manifest 清单.json
python3 -X utf8 scripts/render.py 客户配置.json --manifest 清单.json --out 新的输出目录
```

助手自己填写的原话字段不是安全边界。脚本会核对文件是否存在、音乐是否有音轨、清单哈希是否一致。不要编造用户原话来通过这些检查。

## 效果与验收

打包必须带上 assets/record.png、assets/stars.mov、assets/wave.png。默认 stars_opacity=0.85、wave_opacity=0.22。没有用户要求不得省略。星光为 4 秒循环；音波是图形装饰，不声称根据音乐实时跳动。详见 [效果依据](references/effects.md) 和 [配置说明](references/config.md)。

检查实际视频首、中、尾，确认不切脸、姓名完整、结尾至少停留 6 秒。对比同一照片期间相隔 0.5 秒以上的两帧，确认星光变化。文字必须用透明图层。用户明确要求的静音也要保留星光和音波。

FFmpeg 6.1 使用 `-filter_complex_script` 读取同一份滤镜图。FFmpeg 9.0 移除了这个参数（官方提交 07407ff），脚本改用 `-/filter_complex`，滤镜内容不变。没有实际跑过的版本不要说成已经测过。不要下载来源不明的二进制，也不要覆盖系统里的 FFmpeg。

v0.1 已在 WorkBuddy 应用内实跑；v0.2 的画面在 macOS 上用脚本测过。仅实测 macOS，Windows 未实测。v0.2.3 的引导用本机脚本状态测试和实际导出核对，没有在 Codex 或 WorkBuddy 应用里重放客户对话。更新后应在新会话重新加载。参照原片重新实现效果，不宣称逐帧完全一致。

## WorkBuddy检查

先确认会话有本地文件和执行工具。运行 `scripts/check_environment.py`。通过时只把那句短回复告诉用户，不要念字体路径。缺少 Python 或视频工具时，说明实际缺什么，并协助用户自己准备；未满足系统权限时走应用自己的授权，不要签名或去掉隔离。无需打开剪映。只是安装，或只说「给我跑一下」但没有照片时，检查完就停，并请对方发照片。
